Linux / Kernel Security · relevância alta · confiança alta

Linux Kernel missing initialization for ESP shared fragments

O que mudou: Linux Kernel contém uma vulnerabilidade de inicialização ausente que permite modificar dados page-cache-backed durante coalescimento de socket buffer, causando descriptografia incorreta de fragments compartilhados. Pode ser combinada com CVE-2026-109618 e CVE-2026-109619 para implantar PHP webshells e executar comandos como root.

Por que importa: Esta é uma vulnerabilidade de kernel crítica que permite RCE como root, demonstrando como erros de inicialização podem ser explorados para escalonamento de privilégios. É altamente relevante para estudos de kernel security e forensics.

Aplicação: Projeto de portfólio demonstrando análise de vulnerabilidades de kernel Linux, patch analysis e mitigations.

Secure Coding / CI/CD Security · relevância alta · confiança alta

GitLab CI/CD Regular Expression Integer Overflow

O que mudou: GitLab Community Edition e Enterprise Edition contêm uma vulnerabilidade de overflow inteiro ou wraparound que permite execução arbitrária de código por usuário não autenticado via expressão regular especialmente crafted em configuração CI/CD, devido à validação insuficiente.

Por que importa: Aplica-se ao padrão de secure coding em expressões regulares, demonstrando como validação insuficiente pode levar a RCE. Altamente relevante para estudantes que trabalham com CI/CD pipelines.

Aplicação: Projeto de portfólio demonstrando análise de vulnerabilidades em CI/CD, testes de segurança de expressões regulares e mitigations.

Experimento recomendado

Análise de Vulnerabilidades de Deserialization e Sandbox Escape em Componentes Open-Source

Objetivo: Construir um projeto de portfólio demonstrando análise prática de vulnerabilidades de deserialization e sandbox escape, utilizando componentes open-source com CVEs recentes.

Pré-requisitos

  • Ambiente Docker com container Linux baseado no Ubuntu 22.04 LTS
  • Python 3.10+ com bibliotecas: pickle, requests, flask
  • Node.js 18+ com Stanza e Elo
  • GitLab CE container ou ambiente local com GitLab CI/CD configurado
  • Ferramentas de análise estática: Bandit, Semgrep, Taint-trackers

Passos

  1. 1. Configurar ambiente Docker com Ubuntu 22.04 LTS e instalar Python, Node.js e ferramentas de segurança.
  2. 2. Clone repositorio Stanza e configurar ambiente para reproduzir vulnerabilidade de deserialization pickle.
  3. 3. Criar payload malicioso usando pickle para demonstrar RCE no lemmatizador.
  4. 4. Clone repositorio Elo e configurar ambiente para demonstrar sandbox escape via membro .constructor.
  5. 5. Criar payload malicioso JavaScript para demonstrar bypass de sandbox.
  6. 6. Configurar ambiente GitLab CE container e reproduzir vulnerabilidade de regex integer overflow em CI/CD.
  7. 7. Criar expressão regular maliciosa que cause overflow e demonstre RCE.
  8. 8. Documentar findings com screenshots, logs e análise técnica.

Evidências esperadas

  • Logs mostrando execução de código arbitrário via pickle deserialization
  • Evidências de sandbox escape demonstrando bypass de restrições JavaScript
  • Logs de GitLab CI/CD mostrando execução de código via regex malicioso
  • Documentação técnica com análise de vulnerabilidades e mitigations implementadas

Condição de parada: Quando todas as 4 vulnerabilidades forem analisadas com evidências coletadas e mitigações implementadas, ou após 45 minutos de tempo de execução.

Triagem

Descartados: Sinais duplicados (PHP CVE-2026-109618 e CVE-2026-109619), sinais de menor relevância (WordPress, Ivanti, Cisco, VMware, Brotli, Arista, Collabora, EG Secure, Plex, Arc, payloadcms, odf-kit), sinais de hype sem evidência prática.
