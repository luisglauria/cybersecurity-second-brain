Experimento recomendado

Simulação de Path Traversal e Mitigação em Aplicação Web Local

Objetivo: Demonstrar como validação de entrada e sanitização de caminhos previnem ataques de path traversal em APIs web.

Pré-requisitos

  • Docker instalado
  • Conhecimento básico de Python/Flask
  • Ferramenta de teste de API (curl ou Postman)

Passos

  1. Criar um container Docker com uma API Flask intencionalmente vulnerável a path traversal (ex: /download?file=../../etc/passwd).
  2. Testar o acesso a arquivos sensíveis via parâmetro 'file' sem validação.
  3. Implementar sanitização de caminhos usando bibliotecas como 'os.path' e restringir acesso a diretórios específicos.
  4. Adicionar logs de tentativas de acesso suspeitas e configurar alertas em tempo real.

Evidências esperadas

  • Logs mostrando tentativas bloqueadas de path traversal após mitigação.
  • Código atualizado com validação de caminho e restrições de diretório.
  • Testes automatizados validando que apenas arquivos dentro do diretório permitido são acessíveis.

Condição de parada: Quando a API rejeita 100% das tentativas de path traversal e mantém acesso a arquivos legítimos.

Triagem

Descartados: Vulnerabilidades duplicadas (ex: múltiplas CVEs do Plex) e itens sem aplicação prática direta em estudos ou portfólio.

Backlog

  • Estudo de cadeias de vulnerabilidades SSRF + path traversal em servidores de mídia.
  • Análise de credenciais em logs usando ferramentas como TruffleHog.
  • Simulação de ataque de injeção de comandos em APIs REST com validação de parâmetros.
Uso educacional e defensivo. Execute testes somente em ativos autorizados, laboratórios locais ou dados sintéticos.
