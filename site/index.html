Experimento recomendado

Safe Deserialization Lab: Mitigating Unsafe Pickle RCE

Objetivo: Demonstrate how unsafe deserialization (pickle) can lead to remote code execution and apply a mitigation using a restricted unpickler or JSON serialization.

Pré-requisitos

  • Docker Engine
  • Python 3.9+
  • Basic familiarity with Flask and HTTP requests

Passos

  1. 1. Create a simple Flask app that accepts a POST payload at /data and deserializes it with pickle.loads(request.data).
  2. 2. Build a Docker image for the app and run the container on localhost:5000.
  3. 3. Generate a malicious pickle payload that executes a harmless command (e.g., touch /tmp/pwned) using the __reduce__ method.
  4. 4. Send the payload to the endpoint and verify that the file /tmp/pwned is created inside the container.
  5. 5. Modify the app to replace pickle.loads with json.loads (or use pickle.UnrestrictedUnpickler with a whitelist of safe classes).
  6. 6. Repeat the malicious payload transmission and confirm that /tmp/pwned is NOT created and the request returns an error or safe result.
  7. 7. Log both attempts and compare outcomes.

Evidências esperadas

  • Log or file creation showing /tmp/pwned after the first (vulnerable) request.
  • Absence of /tmp/pwned and an error/safe response after the second (mitigated) request.

Condição de parada: When the mitigated version blocks the malicious payload and no unauthorized file or command execution is observed.
